# Nyxo

Мессенджер со сквозным шифрованием, которое работает прямо в браузере.
Сервер хранит только шифротекст: ни переписку, ни вложения он прочитать не
может.

## Что умеет

- Личные и групповые чаты. Позвать человека в чат можно по коду
  приглашения.
- Сквозное шифрование текста и файлов по протоколам Signal: X3DH и Double
  Ratchet, а в группах от трёх человек — sender keys.
- Несколько устройств на один аккаунт, у каждого устройства свои ключи.
- Сверка ключей по 60-значному коду. Если у обоих собеседников код
  совпал, значит, сервер ключи не подменял.
- Перед отправкой файла из него вычищаются метаданные: координаты и
  модель камеры из фото и видео, автор из PDF. Фото и видео уходят под
  нейтральными именами вроде `photo.jpg`.
- Приватный режим: вход без почты и пароля, аккаунт удаляется при выходе.
- Ответы на сообщения, реакции, удаление с отменой, тёмная и светлая
  темы.
- Сервер можно поднять как скрытый сервис Tor.

Чат с ботом и чат, в который ещё никто не зашёл, не шифруются. Это видно
в шапке чата.

## Как устроено

- `server.js` — сервер на Express и Socket.IO, данные хранятся в
  PostgreSQL.
- `public/` — клиент на обычном JavaScript, без фреймворков. Вся
  криптография лежит в `public/crypto/` и работает на WebCrypto, без
  WASM.
- `e2ee-key-server/` — сервер ключей на Rust (axum, sqlx). Он хранит
  только публичные ключи устройств.
- `anon-service/` — небольшой сервис на Rust, который генерирует
  идентификаторы для приватного режима. Необязательный: если его нет,
  сервер обходится без него.

Ключи личности устройства создаются неизвлекаемыми и хранятся в IndexedDB
браузера, поэтому даже код страницы не может получить их в виде байтов.
Остальные ключи (prekeys и ключи сессий) лежат там же, но выгружаемыми:
состояние сессии приходится сохранять между перезагрузками страницы.

Шифрованные вложения лежат в `encrypted-blobs/`, а открытые (из чата с
ботом и из чатов, где пока нет собеседника) — в `uploads/`. Про устройство
сервера ключей подробнее написано в
[e2ee-key-server/README.md](e2ee-key-server/README.md).

## Запуск

Понадобятся Node.js 18+, PostgreSQL 14+ и Rust. Браузер тоже нужен
свежий: в нём WebCrypto должен уметь Ed25519 и X25519. Актуальные Chrome,
Firefox и Safari это умеют.

```bash
npm install
cp .env.example .env
```

В `.env` нужно прописать `DATABASE_URL`, `SESSION_SECRET` и
`INTERNAL_KEY_SERVER_SECRET` — это общий секрет с сервером ключей, не
короче 32 символов. Сервер ключей запускается отдельно, с тем же
секретом:

```bash
cd e2ee-key-server
DATABASE_URL=postgres://... INTERNAL_SHARED_SECRET=<тот же секрет> cargo run --release
```

По умолчанию он слушает `127.0.0.1:7420`, а основной сервер ищет его
там же (`KEY_SERVER_URL`). Остаётся запустить сам мессенджер:

```bash
npm start
```

Таблицы оба сервера создают сами при первом запуске.

Открывать приложение нужно через `localhost` или по HTTPS. На обычном
HTTP с другого адреса браузер отключает WebCrypto, и шифрование не
заработает.

### Через Tor

Добавьте скрытый сервис в `/etc/tor/torrc`:

```
HiddenServiceDir /var/lib/tor/nyxo/
HiddenServicePort 80 127.0.0.1:3000
```

После перезапуска Tor адрес появится в `/var/lib/tor/nyxo/hostname`. Если
перед сервером стоит прокси, который переписывает заголовок Host, добавьте
этот адрес в `ALLOWED_ORIGINS` в `.env`, иначе сокет не пустит браузер.

## Тесты

Все тесты лежат в `scripts/`.

- `node scripts/test-e2ee-crypto.mjs` и `node scripts/test-metadata.mjs`
  не требуют ни сервера, ни базы.
- Остальным нужен запущенный на порту 3006 сервер вместе с сервером
  ключей и пустая база. Для проверок, которые лезут в базу напрямую,
  нужна ещё переменная `TEST_DATABASE_URL`.
- Браузерным тестам нужны Playwright и Chromium. Пути к ним в скриптах
  пока прописаны жёстко, их придётся поправить под свою машину.

## Что пока не доделано

- На телефоне список чатов закрывает переписку, и чат не открыть.
- История не переносится на новое устройство: старые сообщения на нём
  показываются как недоступные.
- Сверять ключи можно только цифрами, сверки по QR-коду нет.
- Исчезающие сообщения есть в API, но включить их из интерфейса нельзя.
- GIF и WebM уходят без очистки метаданных, а анимированные WebP и APNG
  теряют анимацию.
- GPS-трек, который экшн-камеры и дроны пишут в видео отдельной дорожкой,
  не вычищается.
- Очистка PDF убирает метаданные, но не текст под закрашенными местами:
  если что-то закрыли чёрным прямоугольником, текст под ним остаётся в
  файле.
- PDF с электронной подписью после очистки сохраняется заново, и подпись
  перестаёт проверяться.
- Списка своих устройств в интерфейсе нет: отозвать устройство можно только
  через API, а старые устройства не узнают, что в аккаунт добавили новое.
- Signed prekey не обновляется.
