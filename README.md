# Nyxo Messenger v2.0 🔒

Максимально анонимный и безопасный мессенджер с поддержкой E2EE, Tor routing и автоматическим удалением метаданных.

## ✨ Ключевые возможности

### 🛡️ Безопасность и Приватность
- **End-to-End шифрование (E2EE)** — X3DH и Double Ratchet для текста и
  вложений, ключи привязаны к устройству, обмен через отдельный Rust-сервис;
  в шапке чата видно, шифруется ли он
- **Tor Hidden Service поддержка** — полная анонимность через .onion адреса
- **Автоматическое удаление метаданных** — EXIF из фото (в зашифрованных
  чатах — в браузере до шифрования), метаданные из PDF
- **Disappearing messages** — самоуничтожающиеся сообщения с таймером
- **Защита от timing attacks** — случайные задержки в критических операциях
- **Усиленные заголовки приватности** — CSP, CORS, Permissions Policy
- **Анонимный режим** — полное удаление данных при выходе

### 🎨 Интерфейс
- **Дизайн-система на токенах** — цвет, слои, радиусы, типографика и тени
  объявлены переменными в `:root`; компоненты цвета не хардкодят
- **Тёмная и светлая темы** — переключатель в интерфейсе, выбор сохраняется,
  по умолчанию берётся системная тема. Тема применяется до первой отрисовки
  (`public/theme.js`), поэтому нет вспышки чужого фона на старте
- **Свой знак** — затмение вместо эмодзи; полумесяц оставлен только
  переключателю темы, где он и читается
- **Шкала радиусов** — контейнеры 28px, бабблы 22px, кнопки 16px, поля 12px:
  уровни интерфейса отличаются формой, а не только цветом
- **Иконки набором** — SVG-спрайт вместо эмодзи: один цвет, одна сетка,
  одинаковый вид во всех системах
- **Состояния полей** — фокус и ошибка различимы, ошибка подписана под полем
- **Скелетоны загрузки** — повторяют форму элемента списка, с бегущим бликом
- **Контраст по WCAG AA** — проверен для обеих тем
- **Адаптивный дизайн** — от 320px, без горизонтальной прокрутки
- **`prefers-reduced-motion`** — анимации отключаются по настройке системы

### 💬 Функции мессенджера
- Групповые чаты с кодами приглашений
- Редактирование и удаление сообщений
- Реакции на сообщения (emoji)
- Ответы на сообщения (quotes)
- Поиск по названиям чатов
- Статусы сообщений (отправлено/доставлено/прочитано)
- Загрузка файлов (фото, видео, документы)
- Бот-помощник

- Node.js 18+

- Tor (опционально, для .onion адресов)

### Установка

```bash
# 1. Клонирование репозитория
git clone https://github.com/PortfolioBTS/masages.git
cd masages

# 2. Установка зависимостей Node.js
npm install

# 3. Настройка переменных окружения
cp .env.example .env
# Отредактируйте .env и укажите параметры БД и секреты

# 4. Запуск микросервиса анонимности (Rust)
cd anon-service
cargo run --release &
cd ..

# 5. Запуск E2EE Key Server (Rust) - опционально
cd e2ee-key-server
cargo run --release &
cd ..

# 6. Запуск основного сервера
npm start
```

### Конфигурация Tor (опционально)

Для максимальной анонимности через Tor:

```bash
# 1. Установка Tor
# Ubuntu/Debian:
sudo apt install tor

# macOS:
brew install tor

# 2. Настройка Hidden Service
# Добавьте в /etc/tor/torrc:
HiddenServiceDir /var/lib/tor/nyxo/
HiddenServicePort 80 127.0.0.1:3000
HiddenServiceVersion 3

# 3. Перезапуск Tor
sudo systemctl restart tor

# 4. Получение .onion адреса
sudo cat /var/lib/tor/nyxo/hostname

# 5. Включение Tor routing в .env
ENABLE_TOR_ROUTING=true
TOR_PROXY_HOST=127.0.0.1
TOR_PROXY_PORT=9050
```

## 🔐 Безопасность

### Реализованная защита

1. **Content Security Policy (CSP)** — nonce-based, запрещает inline скрипты
2. **CSRF Protection** — double-submit cookie pattern с улучшениями
3. **Rate Limiting** — защита от bruteforce на всех критических эндпоинтах
4. **Magic Bytes Verification** — проверка реального типа файлов
5. **Metadata Stripping** — автоматическое удаление EXIF и метаданных
6. **Timing Attack Protection** — случайные задержки в аутентификации
7. **Параметризованные запросы** — защита от SQL-инъекций
8. **WebSocket авторизация** — проверка сессий перед подключением
9. **Защищенная раздача файлов** — контроль доступа на уровне участников
10. **Enhanced Privacy Headers** — полный набор заголовков безопасности

### E2EE Implementation

Мессенджер использует модифицированный X3DH протокол:

- **Два identity-ключа** вместо одного (Ed25519 для подписей, X25519 для DH)
- **Signed PreKey** с ротацией для forward secrecy
- **One-Time PreKeys** пул для каждой новой сессии
- **Сервер не видит приватные ключи** — только публичный материал

### Что зашифровано, а что нет

**Зашифровано:** текст и вложения в чатах, где есть хотя бы одно чужое
устройство. Сервер хранит только шифротекст — в `messages.text` у таких
сообщений `NULL`, содержимое живёт в конвертах `message_envelopes`.

Шифруется ли конкретный чат, видно в его шапке: «Сквозное шифрование» либо
«Без шифрования» с причиной (бот, собеседника пока нет, ключи устройства
недоступны). Зашифрованные сообщения помечены замком.

**Вложения** шифруются так же, как у Signal: у каждого файла свой случайный
ключ AES-256-GCM, на сервер уходят непрозрачные байты, а ключ, имя и тип
файла едут внутри E2EE-сообщения. Сервер знает только размер шифротекста.
Лежат такие файлы в `encrypted-blobs/`, а не в `uploads/`, и удаляются
вместе с сообщением — в том числе исчезающим.

Раз сервер файл больше не видит, срезать EXIF он не может — это делает
браузер до шифрования: JPEG, PNG и WebP перерисовываются через canvas,
ориентация снимка при этом вшивается в пиксели. Если перерисовать не
вышло, файл не отправляется: тихо отправить фото с координатами хуже, чем
не отправить его вовсе.

Что об этом нужно знать:
- **GIF не перерисовывается** — canvas сохранил бы только первый кадр.
  EXIF в GIF не бывает, GPS там на практике не встречается.
- **Видео и PDF уходят собеседнику как есть**, с метаданными. Видео и
  раньше не чистилось; метаданные PDF раньше срезал сервер, теперь их
  увидит получатель (сервер по-прежнему не видит).
- Всё, что не картинка и не видео из белого списка, открывается только
  скачиванием: тип расшифрованного файла берётся из белого списка, а не
  из того, что объявил отправитель, иначе присланный HTML исполнился бы в
  origin мессенджера рядом с ключами.

**Не зашифровано:**
- **чаты с ботом** — бот отвечает на открытый текст. Сервер не считает
  получателями бот-чата даже другие устройства его владельца
- **метаданные** — кто, кому, когда и сколько. X3DH их не скрывает, и
  скрытие потребовало бы mixnet, что прямо вне принятой модели угроз

### Клиентская реализация — без WASM

Роадмап предполагал WASM-модуль, но всё нужное есть в WebCrypto: X25519,
Ed25519, HKDF, AES-GCM. Это не компромисс, а выигрыш: identity-ключи
устройства создаются с `extractable: false` и хранятся в IndexedDB
структурным клонированием, то есть приватный ключ никогда не появляется в
памяти JS как байты. Сборке libsignal на WASM нужны сырые байты ключа в
линейной памяти, и такого она дать не может.

`public/crypto/` — `e2ee.js` (X3DH и Double Ratchet, чистый WebCrypto),
`store.js` (IndexedDB), `client.js` (связывание с сетью).

⚠️ **История не переносится на новые устройства.** Ключ сообщения в Double
Ratchet одноразовый, и расшифрованный текст кэшируется локально. Новое
устройство видит на старых сообщениях заглушку «недоступно на этом
устройстве», а очистка данных сайта теряет историю безвозвратно.

## 🎯 Новые API эндпоинты

### Disappearing Messages

```javascript
// Установка таймера самоуничтожения для сообщения
POST /api/messages/:messageId/set-expiry
Body: { expirySeconds: 3600, autoDeleteOnRead: false }

// Настройка автоудаления для чата
POST /api/chats/:chatId/set-default-expiry
Body: { expirySeconds: 3600 }

// Получение настроек чата
GET /api/chats/:chatId/settings
```

### E2EE Key Management

```javascript
// Регистрация identity ключей
PUT /api/keys/identity
Body: { identity_signing_key: "base64", identity_dh_key: "base64" }

// Ротация Signed PreKey
PUT /api/keys/signed-prekey
Body: { key_id: 1, public_key: "base64", signature: "base64" }

// Пополнение One-Time PreKeys
POST /api/keys/one-time-prekeys
Body: { keys: [{ key_id: 1, public_key: "base64" }, ...] }

// Получение bundle для начала сессии.
// Отдаёт НАБОР bundle — по одному на каждое устройство получателя:
// { "bundles": [ { "device_id": 1, "identity_signing_key": ..., ... }, ... ] }
// Отправитель обязан зашифровать сообщение для каждого элемента набора,
// иначе на части устройств получателя оно не расшифруется.
GET /api/keys/bundle/:targetUserId

// Количество оставшихся OPK у текущего устройства
GET /api/keys/one-time-prekeys/count

// Удаление всех ключей аккаунта (по всем устройствам)
DELETE /api/keys
```

Все операции с ключами, кроме bundle и удаления аккаунта, выполняются от
имени устройства. `device_id` берётся из серверной сессии и никогда из
запроса, поэтому подделать принадлежность устройства нельзя — сначала
нужно зарегистрировать устройство.

### Отправка зашифрованного сообщения

```javascript
// Одно сообщение = N конвертов, по одному на каждое устройство каждого
// участника чата, включая ДРУГИЕ устройства самого отправителя. Своему
// устройству конверт не нужен: отправитель хранит своё локально.
POST /api/messages/encrypted
Body: {
  chatId: 12,
  replyToId: null,
  blobIds: [],        // зашифрованные вложения этого сообщения, до 10
  envelopes: [
    { recipientDeviceId: 1, envelopeType: 1, header: "base64", ciphertext: "base64" },
    { recipientDeviceId: 2, envelopeType: 2, header: "base64", ciphertext: "base64" }
  ]
}
// envelopeType: 1 — prekey (первое сообщение сессии X3DH), 2 — обычное
// header — заголовок ratchet; сервер внутрь не смотрит, но обязан вернуть
//          его байт в байт: он используется как AAD при AES-GCM
// Ответ содержит missingDeviceIds — устройства чата, для которых конверта
// не прислали: там сообщение не прочитается, клиент должен добрать ключи.
```

`GET /api/messages/:chatId` добавляет к зашифрованным сообщениям поле
`envelope` — только тот конверт, что адресован текущему устройству. Если
конверта нет (устройство подключили после отправки), приходит
`envelope: null`, и клиент обязан показать заглушку.

Открытые пути `POST /api/messages` и `POST /api/messages/file` оставлены
рядом: ими пользуются чаты с ботом и чаты, в которых пока не для кого
шифровать.

### Зашифрованные вложения

```javascript
// Загрузить шифротекст файла. Тело — сырые байты, до 50 МБ.
// Вложение привязывается к чату, но не к сообщению: сообщение ещё не
// отправлено. Не отправленное за час вложение удаляется.
POST /api/blobs?chatId=12
Content-Type: application/octet-stream
// → { success: true, blobId: "32 hex-символа" }

// Скачать шифротекст. Доступ — у участников чата, куда ушло сообщение,
// до отправки — только у загрузившего. Во всех остальных случаях 404,
// одинаковый для «нет такого» и «нет доступа».
GET /api/blobs/:blobId
```

Ключ файла сервер не получает никогда. Привязать к сообщению можно только
своё, ещё не отправленное вложение из того же чата — иначе чужой файл
можно было бы «переотправить» в другой чат.

### Управление устройствами

```javascript
// Зарегистрировать текущую сессию как устройство
POST /api/devices
Body: { name: "Ноутбук" }

// Привязать к новой сессии уже существующее своё устройство
// (нужно после повторного входа: приватные ключи остались в браузере)
POST /api/devices/:id/bind

// Список своих устройств
GET /api/devices

// Отозвать устройство: помечается revoked_at и удаляется его ключевой
// материал на key-server. Отозванное устройство нельзя привязать заново.
DELETE /api/devices/:id
```

В приватном режиме доступно ровно одно устройство: multi-device там
отключён осознанно (у анонимного аккаунта нет пароля, а значит нет и
способа аутентифицировать второе устройство), но одно устройство нужно,
иначе самый приватный режим остался бы единственным без E2EE.

## 🤝 Безопасное использование

### Рекомендации

1. **Всегда используйте HTTPS** в production
2. **Настройте Tor** для максимальной анонимности
3. **Регулярно обновляйте** зависимости
4. **Используйте сильные пароли** для БД и секретов
5. **Настройте firewall** для закрытия неиспользуемых портов

### Ограничения

- Ключи собеседника пока не сверяются (нет safety numbers): при первом
  контакте подменить их может тот, кто контролирует сервер
- История не переносится на новое устройство
- Группы шифруются попарно, без sender keys: сообщение в группу из N
  устройств — это N конвертов
- Видео и PDF в зашифрованных чатах уходят с метаданными
- Voice/Video звонки не реализованы
